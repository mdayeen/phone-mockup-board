# Contributing to phone-mockup-board

Thanks for taking the time to contribute!

## Workflow

1. Fork the repository and create a branch from `main` (e.g. `feat/drag-snap`, `fix/export-crash`).
2. Make your changes in small, focused commits.
3. Rebase on the latest `main` before opening a pull request (history on `main` is kept linear).
4. Open a pull request against `main` and fill in what changed and why.

## Pull request rules

`main` is protected:

- Direct pushes, force-pushes and branch deletion are blocked.
- Every PR needs **1 approving review**; new commits dismiss earlier approvals.
- All review conversations must be resolved before merging.
- PRs are merged with **squash** or **rebase** (no merge commits).

## Commit messages

We follow [Conventional Commits](https://www.conventionalcommits.org/), e.g. `feat: add device frame picker` or `fix: correct mockup scaling`.

## Reporting bugs and requesting features

Open an issue with steps to reproduce, expected vs. actual behaviour, and screenshots if relevant.
For security issues, follow [SECURITY.md](SECURITY.md) instead.
